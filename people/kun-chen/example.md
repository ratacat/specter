# `/vision` → VISION.md (acceptance policy)

Not a feature list. A future reader (human or agent) applies it to a concrete PR.

## Anatomy (40–70 lines)

```
# Vision
`{project}` exists so that {one-sentence reason}.
It serves {named user}, and it {turns their input into}.
It owns exactly one thing: {single owned surface}.

## {3–6 principle headings}
{Declarative present-tense commitments and refusals. One sentence per line.}

## Scope
{Named non-goals. What stays private. How the repo holds itself to this.}

A change aligns when {testable positives}.
A change should be resisted when {testable negatives}.
```

Hard rules: every line traces to a named PR/commit or a recorded author verdict. Generic virtues banned. Author never auto-approved. One sentence per line. No em dashes, no roadmap, no marketing.

## Pipeline

1. Mine 30–100 merged PR titles; read 8–15 bodies. Private evidence sheet: value → PRs.
2. Draft (or delta an existing VISION.md — never a competing doc).
3. 8–12 hypotheticals on genuine fault lines; steelman both sides; if you can predict the answer, replace it.
4. Review loop on lavish-axi (full draft left, one card at a time). Each verdict → named changelog line.
5. Deliver approved VISION.md + answers file (durable calibration).

## firstmate closer (the actual spec)

`firstmate` owns the layer between captain intent and the agents. Align when it deepens peace of mind, shipped outcomes per attention, safer delegation, refusal paths, introspectability. Resist when it adds noise, acts beyond adjudicable intent, assumes consent, adds a layer, mixes script with judgment, or couples to one vendor.
